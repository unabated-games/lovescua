# LÖVE + SCUA

This is an altered LÖVE 12 development fork. The SCUA integration replaces
Lua's startup and bindings with a C++ host linked to **SCUA 0.39 preview / ABI 3**.
The pinned source still reports 0.38.0. It uses
LÖVE's actual window, graphics, font and image implementations. Game logic runs
in SCUA; there is no Lua interpreter or Lua dependency in `lovescua`.

The host supports **macOS**, with Metal by default and OpenGL as an alternative.
The integration now exposes hundreds of native functions for graphics, fonts,
images, audio, math, physics, windowing and input, plus a SCUA filesystem facade.
See the generated [API inventory](SCUA_API.md) for exact signatures. This remains
a SCUA-oriented port: the supported surface and deliberate API differences are listed
below and in the [upstream method audit](SCUA_COMPATIBILITY.md).

The sprite lab loads an original four-direction, four-frame robot sheet. Arrow
keys or WASD take control; Space toggles autoplay, R resets, and Escape quits.
Its [`main.scua`](examples/sprite/main.scua) handles drawing and input, while
[`controller.scua`](examples/sprite/controller.scua) holds movement and animation
in a typed record with direction/motion enums. Diagonal input is normalized.
The sheet is generated by `python3 examples/sprite/make_sheet.py`, using only
Python's standard library.

In the bounce demo, Space pauses, R resets, Escape quits. The window is resizable. The example uses
a typed `Ball` record, `vec2` movement and swizzles, `vec4` colors, collection
slicing and pattern matching. Its game logic is in
[`examples/bounce/main.scua`](examples/bounce/main.scua).

## Build

You need Xcode command line tools, CMake, FreeType, HarfBuzz, zlib, Vorbis/Ogg
and OpenAL Soft, plus the **SCUA
embedding SDK with the 0.39 follow-ups** (or the pinned source-built preview in
[SCUA_ACTORS.md](SCUA_ACTORS.md#sdk-and-verification)). The installed `scua` command alone is not enough: the
host needs the matching `include/scua.h` and `lib/libscua.a` from the SDK.
Python 3 and the `scua` 0.38 command are needed when `BUILD_TESTING` is enabled
(the default).

Set `SCUA_SDK_DIR` to your extracted SDK directory, then:

```sh
cmake -S . -B build -DLOVE_SCUA=ON \
  -DSCUA_ROOT="$SCUA_SDK_DIR" \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=/opt/homebrew \
  -DLOVE_SCUA_FETCH_SDL=ON -DLOVE_SCUA_FETCH_OPENAL=ON -DLOVE_SCUA_FETCH_MODPLUG=ON
cmake --build build --target lovescua -j 2
```

`LOVE_SCUA_FETCH_SDL=ON` builds a pinned, SHA-256 checked SDL 3.2.28 archive if
SDL3 is not installed. Omit the option to require an installed SDL3 instead.
For offline builds, supply an extracted SDL source tree with
`-DFETCHCONTENT_SOURCE_DIR_SDL3=/path/to/SDL3-3.2.28` as well as the fetch option.
Audio is enabled by default (`LOVE_SCUA_AUDIO=ON`).
`LOVE_SCUA_FETCH_OPENAL=ON` builds pinned OpenAL Soft 1.24.3 with its archive
SHA-256 verified. Without that option, CMake requires an installed OpenAL.
`LOVE_SCUA_FETCH_MODPLUG=ON` builds the pinned libmodplug source snapshot
`d1b97ed0020bc620a059d3675d1854b40bd2608d` with SHA-256 verification. Its
private loader copies disable ambient file reads; tracker data must come from
explicit resource bytes. Without this option, CMake requires installed ModPlug.
Theora/Ogg are required for video even with audio disabled; Vorbis is required
for audio (for example, `brew install libtheora libvorbis`).
`-DLOVE_SCUA_AUDIO=OFF` omits the audio and sound modules; other examples still run.
For offline audio builds, add
`-DFETCHCONTENT_SOURCE_DIR_OPENAL_SOFT=/path/to/openal-soft-1.24.3` and
`-DFETCHCONTENT_SOURCE_DIR_MODPLUG=/path/to/libmodplug-d1b97ed0020bc620a059d3675d1854b40bd2608d`.
Use `/usr/local` instead of `/opt/homebrew` for an Intel Homebrew installation.

For this workspace, the matching SDK is built in `build/scua-sdk-0.39-preview` from a
pinned SCUA source snapshot. See [SDK build instructions](SCUA_ACTORS.md#sdk-and-verification)
to reproduce it. SDL source in `build/vendor/SDL3-3.2.28` is a fallback; the current
build uses installed SDL 3.4.18. These and OpenAL Soft in
`build/vendor/openal-soft-1.24.3` are local, ignored build inputs. The existing
CMake cache already points to them. To configure again using them:

```sh
cmake -S . -B build -DLOVE_SCUA=ON \
  -DSCUA_ROOT="$PWD/build/scua-sdk-0.39-preview" \
  -DLOVE_SCUA_FETCH_SDL=ON \
  -DFETCHCONTENT_SOURCE_DIR_SDL3="$PWD/build/vendor/SDL3-3.2.28" \
  -DLOVE_SCUA_FETCH_OPENAL=ON \
  -DFETCHCONTENT_SOURCE_DIR_OPENAL_SOFT="$PWD/build/vendor/openal-soft-1.24.3" \
  -DLOVE_SCUA_FETCH_MODPLUG=ON \
  -DFETCHCONTENT_SOURCE_DIR_MODPLUG="$PWD/build/vendor/libmodplug-d1b97ed0020bc620a059d3675d1854b40bd2608d" \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/opt/homebrew
```

The upstream Lua build remains available with `LOVE_SCUA=OFF` and its original
dependencies. Upstream's source lists are reused; the SCUA target filters out
the Lua wrappers, `runtime.cpp` and `Reference.cpp`. Metal is compiled with
ARC, matching upstream's Xcode configuration.

## Script lifecycle

The host loads a `.scua` file, or `main.scua` from a directory. It compiles the
script once and pins callbacks across frames. The callbacks are ordinary
top-level functions:

```scua
import love

fn load()
  love.window.set_title("My SCUA game")
end

fn update(dt: float)
  -- dt is elapsed seconds, clamped to 0.25 after a long frame.
end

fn draw()
  love.graphics.clear(vec4(0.04, 0.05, 0.09, 1))
  love.graphics.set_color(vec4(0.2, 0.9, 0.7, 1))
  love.graphics.circle("fill", vec2(200, 200), 32)
end

fn keypressed(key: string)
  if key == "Escape" then love.event.quit() end
end
```

Only `draw()` is required. Optional callbacks are:

| Callback | Arguments |
| --- | --- |
| `load`, `draw`, `quit`, `verify` | none |
| `update` | elapsed seconds as `float` |
| `post_update` | elapsed seconds as `float`, after actor/deferred work |
| `keypressed`, `keyreleased` | SDL scancode name as `string` |
| `resize` | logical size as `vec2` |
| `mousepressed`, `mousereleased` | position `vec2`, button `int` (1 left, 2 right, 3 middle) |
| `mousemoved` | position `vec2`, relative movement `vec2` |
| `wheelmoved` | scroll amount `vec2` |
| `textinput` | UTF-8 text `string` |
| `textedited` | composition `string`, start `int`, length `int` |
| `focus`, `mousefocus`, `visible` | state `bool` |
| `touchpressed`, `touchreleased`, `touchmoved` | finger ID `int`, pixel position `vec2`, pressure `float` |
| `joystickadded`, `joystickremoved` | instance ID `int` |
| `joystickpressed`, `joystickreleased` | instance ID `int`, zero-based button `int` |
| `joystickaxis` | instance ID `int`, zero-based axis `int`, value `float` |
| `gamepadpressed`, `gamepadreleased` | instance ID `int`, SDL gamepad button name `string` |
| `gamepadaxis` | instance ID `int`, SDL gamepad axis name `string`, value `float` |
| `event` | custom name `string`, payload `any` |

`quit()` is a shutdown notification and does not veto closing. Key names include
`"Escape"`, `"Space"`, `"R"` and `"Left"`. Repeats call `keypressed` only after
`love.keyboard.set_key_repeat(true)`. Held keys use `love.keyboard.is_down`.
`love.event.post(name, payload)` queues a custom event for the next frame and
retains its SCUA payload through delivery. Posting from `event()` delivers on a
later frame; the queue is limited to 256 entries. The events example uses an enum
and a typed message record.

The main script and engine work run on the owner thread. Actor workers are opt-in;
all existing engine natives stay classified main-thread, with copied-data bridge
operations explicitly classified for parallel reads/deferred results. Each frame has a handle scope; cached callbacks and queued event payloads remain pinned. Native calls validate arguments and catch C++
exceptions before they can cross the C ABI. Main callback/native faults print a located error and exit with status 1.
Actor/task faults, including actor operation-budget exhaustion, are reported once
and leave other work and the actor's next message runnable. Unhandled Error results
are reported separately as `kind="error"`. Each callback has a one-million-step
budget and the main script partition has a 64 MiB memory cap. Actor heaps add
memory usage; the bridge does not impose an aggregate actor-memory quota.

The host grants no general filesystem, network or process capabilities. SCUA's
`fs` module can read the project's `res:` resources. Saves require an explicit
`--save-dir DIRECTORY` or `--user-id APP_ID` grant and use `user:` paths. General
host paths remain unavailable. The entry script and its imports use the embedding API. Drawing functions
must be called during `draw()`. At the start of each frame the host resets the
transform and color and clears the configured background color; the script can then clear and
draw its own scene.

Import optional native modules in a game as `import love_audio as audio` and
`import love_sound as sound`. Import the SCUA `filesystem` facade separately;
that import requires project resources, a resource mount, or an explicit user
folder grant. It returns SCUA `Ok`/`Error` values rather than Lua-style multiple
returns. Bare read paths mean `res:`; bare write paths mean `user:`. To read a
save, use `user:saves/slot.json` explicitly.

SCUA reserves method names such as `push`, `pop` and `remove` for its collection
operations. Graphics uses `push_state()` / `pop_state()` and the filesystem
facade uses `remove_file()`. Numeric indices in the new APIs are zero-based;
PCM channel numbers remain one-based to match the engine.

Coordinates use logical drawing pixels, including on Retina displays. Vectors
cross the C boundary as SCUA values. Mesh vertices can be typed SCUA records with
`position: vec2`, `uv: vec2`, and `color: vec4`. Engine objects are opaque managed
values with runtime type checks; their declaration type is currently `any`. The optional
`handles` facade adds 28 resource record types with enum brands and checked factories.
Pass `wrapper.raw` to native functions. See [runtime and lifecycle details](SCUA_RUNTIME.md)
for CPU image formats, typed wrappers, desktop services, logical saves and hot reload.

[`binding_util.h`](scua/binding_util.h) shares argument checks, the exception
boundary, result construction and retained engine-object ownership. Individual
modules live in `graphics.cpp`, `objects.cpp`, `drawables.cpp`, `batches.cpp`,
`math.cpp`, `data.cpp`, `audio.cpp`, `physics.cpp`, `video.cpp`, `rendering.cpp`,
`buffers.cpp`, `textures.cpp`, `fonts.cpp`, `particles.cpp`, `input.cpp`, and `platform.cpp`.
[`main.cpp`](scua/main.cpp) owns the engine lifecycle and callback loop.

## Load and draw a sprite

Place the PNG in the game's `res/` folder, next to its `scua.toml`. This is the
resource layout used by `examples/sprite`:

```scua
import love
import assets

let image = nil
let frame = nil

fn load()
  image = assets.image("res:robot.png")
  love.graphics.set_filter(image, "nearest")
  frame = love.graphics.new_quad(image, vec2(0, 0), vec2(32, 32))
end

fn draw()
  love.graphics.draw_quad(frame, vec2(300, 250), 0.0, vec2(4, 4), vec2(16, 28))
end
```

`assets.image` reads the encoded bytes using SCUA's resource API, then passes
them to LÖVE's decoder. Read/decode failures become catchable script faults.
The native layer never opens a script-supplied host path. You can also pass
encoded bytes directly to `love.graphics.new_image`.

Draw transforms use a `vec2` position, a rotation in radians (default `0`), a
`vec2` scale (default `vec2(1, 1)`) and a `vec2` local origin (default zero).
Negative scale flips the image. Current drawing color tints images, including
alpha. Quads store their source image, so `draw_quad` needs only the region.
Regions must have positive size and fit inside their source image.

Additional resource directories or SCUA resource packs can be mounted above
the game's default resources, in argument order:

```sh
scua res build examples/sprite/res -o build/sprites.pak
./build/lovescua --mount build/sprites.pak examples/sprite
```

`--mount` is repeatable and grants no host filesystem writes. A later mounted
layer overrides an earlier one. SCUA validates the pack and resolves `res:`
paths, including reads made from imported modules.

## Contacts, video and advanced examples

`examples/contacts/main.scua` defines `begincontact`, `endcontact`, `presolve` and
`postsolve`. They run synchronously inside `world_step`, using SCUA 0.38's
supported reentrant call API. A callback receives a snapshot record with world
and body/collider IDs, normal, points, material settings and post-solve impulse vectors.
The record can be saved in script state after the callback returns. `presolve`
may return `{enabled=false}` or friction/restitution/tangent-speed overrides;
return nil to keep the current settings. This lets a game disable a collision
before the solver runs.

World/body/collider/joint operations on the stepping world fault while Box2D is
locked. Defer such work until `world_step` returns, using the record's IDs to
identify objects. A callback fault propagates after Box2D unlocks, so a surrounding
SCUA `pcall` can handle it. A step permits at most 4096 callback invocations and
shares its caller's execution budget. Notifications are delivered during
`world_step`; explicit destruction outside a step does not invoke `endcontact`.
The joints demo covers distance, revolute, prismatic, wheel, weld, friction,
motor, mouse, pulley, rope and gear joints with their supported controls.

`collider_id` identifies fixtures within a world. Contact and ray snapshots carry
these IDs alongside body IDs. `world_query` returns broad-phase bounding-box
candidates, sorted by collider ID; candidates can include shapes near the query
rather than exact overlaps. `world_raycast_all` returns hits sorted by fraction.
Both collect native results before building SCUA records and limit output to 4096.
The physics example checks these queries, inverse point transforms, point velocity,
forces/impulses at world points, torque and gravity scale. Inertia, torque and
angular impulse use pixel-squared units consistent with the world's meter scale.

`examples/physics_controls` covers the extended physics API. `world_configure`
sets sleep/warm-start/continuous/sub-step/force-clearing policies; `world_settings`
and `world_profile` report current settings and native timing/tree statistics.
Origin shifting, explicit force clearing, and solver iteration counts are exposed.
Bodies support custom mass/center/inertia records, sleep policy, vector and batch
point transforms. Shape snapshots include local geometry, adjacency, materials
and collision filters; shape queries return bounds, mass, closest points and ray
hits. `collider_configure` validates all supplied values before changing a shape.

`new_joint(kind, a, b, settings)` creates distance, revolute, prismatic, wheel,
weld, mouse, friction, motor, pulley or rope joints. Settings include
`collide_connected`, world `anchor` or `anchor_a`/`anchor_b`, optional
`local_anchor_a`/`local_anchor_b`, `axis`, `reference_angle` and the family's
configurable properties. Pulley settings use `ground_a`, `ground_b` and `ratio`;
its ratio is fixed at construction. Gear joints use `new_gear_joint` with two
revolute/prismatic sources, ratio and optional collision flag. Rope uses a native
distance joint with a maximum length, so its reported native kind is `distance`.
`joint_info` includes common and family properties; `joint_state(joint, dt)` adds
measured motor force/torque when dt is supplied. `joint_configure` checks the
entire record before applying supported properties: motor/limit settings,
distance lengths, stiffness/damping, mouse target, force/torque bounds, motor
offsets/correction and gear ratio. Linear values use pixels; torque/inertia and
angular spring coefficients use pixel-squared units. Linear stiffness/damping
retain their native force-per-distance units. `joint_set_spring` accepts frequency
and damping ratio instead of raw coefficients.

World/body lookup and list APIs return retained aliases with shared lifetime
state. Closing a script handle releases that alias; explicit body, collider,
joint or world destruction invalidates every alias for the destroyed native
object. Destroying a gear source also destroys dependent gears. Body/collider/
joint IDs are stable and scoped to their world. Keep game data in typed SCUA
entity records containing these handles or IDs; arbitrary VM values are not
stored in Box2D's native user-data slots.

`world_query_each` invokes a callback for each broad-phase candidate; return true
to continue or false to stop. `world_raycast_each` passes hit snapshots; return -1
to ignore a hit, 0 to stop, a fraction in [0,1] to clip the ray, or nil to continue.
These callbacks follow native traversal order, with at most 4096 invocations.
Queries lock their world against mutations, and unlock before propagating errors.
Global `contactfilter(pair)` runs after native category/group/mask filtering and
returns a boolean; dispatch by the snapshot's world ID for per-world behavior.
It shares the step's callback budget and lock guard, including early pair discovery.

`world_contact_list` and `body_contact_list` return full contact snapshots with
IDs that remain valid while touching. `contact_info(world,id)` returns nil after
retirement. `contact_set(world,id,settings)` edits friction, restitution,
`tangent_speed` and an enabled override reapplied at every pre-solve until reset.
`contact_reset` restores mixed materials and clears overrides. Contact operations
are allowed inside contact callbacks; other operations on the stepping world
remain guarded. `world_set_callbacks_enabled` disables callback delivery. A saved
snapshot remains ordinary script data after its native contact is retired.

`examples/video/main.scua` reads Theora bytes through `fs.read`, creates a managed
video, and calls `love.video.update(video, dt)` from `update`. Decoding runs on the
main thread and accepts a step in [0, 0.25] seconds. The demo plays an original
8-second clip with moving shapes, a frame counter, progress bar and quiet audio
ticks. It loops automatically; Space pauses/resumes and R restarts playback.
`set_source(video, audio_source)` retains and synchronizes an external audio
source; nil restores delta timing. `new(encoded, audio=true)` automatically
demultiplexes the first embedded Vorbis logical stream, including logical serial
zero, and synchronizes video to its retained streaming source. `source(video)`
returns a retained source alias or nil. Pass false for deterministic video-only
stepping. Audio-disabled builds default to video-only and reject explicit true.
The demo includes Vorbis; CTest uses the silent audio driver. Encoded video is
bounded to 32 MiB and frame dimensions to 4096. The previous upstream logo fixture
contains less than one second of video and remains available for codec regressions.
`python3 examples/video/make_video.py` regenerates `res/motion.ogv` from original
procedural shapes and tones, using a C compiler, pkg-config, libtheora/libogg and
FFmpeg. Regeneration tools are not needed to run the checked-in clip.

Video tests exercise the actual demo and compare rendered pixels at different
playback positions, including pause, rewind and restart after EOF. The demo's
keyboard/looping logic also has a window-free regression.

`examples/rendering/main.scua` writes two canvases in one shader, uses a temporary
depth/stencil attachment, and reads back the resulting pixels asynchronously.
`set_canvases([a,b], depth, stencil)` selects color targets; an empty array restores
the window. Unbind a texture before reading it back. Poll a transfer with
`readback_status`, then call `readback_image` when complete; `readback_wait` provides
a blocking path. Shader arrays accept arrays of scalars/vectors, with flat arrays
for integer vectors and matrices. Matrices use row-major input by default;
`shader_send_matrix` also accepts an explicit column-major flag.

`examples/audio_queue/main.scua` uses typed parameter records, refills a queueable
source, and decodes Ogg in PCM chunks. Scene effects and source filters accept an
array of `{name="gain", value=0.3}` records. Unknown or duplicate names fault.
`effects_info()` reports driver support and limits. Audio cone angles pass through
the engine's integer-degree representation, so readback is approximate. Capture
is explicit through `recording_names`, `recording_get`, `recording_start` and
`recording_data`; no example or automated test opens the microphone. Capture and
physical sensor hardware remain unverified on this machine.

`examples/audio_controls` checks the remaining controls against OpenAL's silent
backend. `source_info` reports transport, gain limits, attenuation and spatial
state. Sources support sample-based seeking, decoder-cloned streams, gain bounds,
air absorption, and grouped play/pause/stop; `pause_all` returns retained aliases.
Effect/filter getters return typed `{name,value}` parameter arrays, and
`attach_effect_filtered` applies a filter to a source's effect send. Playback
outputs can be enumerated/reopened, with HRTF, system-mix and context pause/resume
controls subject to native device support. These calls report actual capabilities
or failure rather than emulating unsupported settings.

PCM copying uses the engine's 8/16-bit conversion. Tracker modules decode through
ModPlug, with finite EOF and seek/rewind recovery; source looping is explicit.
The pinned static decoder includes its upstream license in runtime modules and
packages. CPU-only tests check Ogg demux bounds, tracker/Vorbis EOF and restart,
and absence of file-opening imports in the bundled tracker decoder. Physical
playback switching, HRTF listening and microphone capture are not hardware-tested.

## GPU buffers and instancing

`examples/instancing/main.scua` draws 1600 triangles using one instanced mesh draw.
Its per-instance positions and colors are typed SCUA records uploaded in a batch:

```scua
record Instance { offset: vec2, tint: vec4 }
let instances = love.graphics.new_buffer([
  {name="offset", format="floatvec2"},
  {name="tint", format="unorm8vec4"},
], 1600)
love.graphics.buffer_set_data(instances, rows)
love.graphics.mesh_attach_attribute(mesh, "InstanceOffset", instances, "offset", "perinstance")
love.graphics.mesh_attach_attribute(mesh, "InstanceTint", instances, "tint", "perinstance")
-- Inside draw(), with a shader declaring the matching attributes:
love.graphics.draw_instanced(mesh, 1600, vec2(0, 0))
```

`new_buffer` takes an array of `{name, format}` records, an element count, optional
usage strings and an access hint. Usages default to `["vertex"]`; an empty array
creates a general copy/readback buffer. Other engine-supported usages are `index`,
`texel`, `shaderstorage` and `indirectarguments`; support depends on the renderer.
Access hints are `dynamic`, `static`, `stream` and `readback`. Each allocation is
zeroed and limited to 32 MiB, 1,048,576 elements, 16 members and a 2048-byte stride.
`buffer_info` reports the actual native member offsets and stride.

Uploads accept named records, or scalar/vector values for a single-member format.
Float, signed/unsigned integer, normalized integer, boolean and matrix data use
the native format names. Matrices take flat row-major arrays. Integer ranges,
component widths, finite values and normalized [-1,1]/[0,1] ranges are checked.
The entire batch is validated before touching GPU memory. `buffer_set_bytes`
provides raw byte uploads using the reported native layout.

`mesh_from_buffer` retains a custom vertex buffer; `mesh_attach_attribute` retains
additional attributes with `pervertex` or `perinstance` stepping. Closing the
original buffer wrapper leaves the mesh usable. Meshes made from external buffers
are updated through their buffers; the older `mesh_set_vertex` API requires a
mesh with its own standard-format CPU vertex data. Instanced draws check that all
enabled per-instance buffers contain enough elements. `shader_send_buffer` binds
an active texel or storage-buffer uniform.

`copy_buffer` performs GPU copies with checked ranges and four-byte alignment.
`buffer_read` copies contents to SCUA bytes synchronously; `buffer_read_async`
returns the same managed transfer type as texture readback. Use `readback_status`,
`readback_wait` and `readback_bytes` for that asynchronous result. The instancing
example checks uploads, rejected batches, copies, retained resources, asynchronous
readback and pixels from both the first and last rendered instance in one window.

## Indexed drawing, compute and shader resource arrays

`examples/compute/main.scua` combines retained index buffers, sampler arrays,
texel-buffer arrays, compute-generated vertex data and indirect draws. Its GLSL
sources live under `examples/compute/res/`. On Metal it dispatches the compute
kernel directly, reads back the first result, then dispatches it indirectly with
different uniforms and draws the generated geometry. macOS OpenGL uses the
indexed/array path and checks that unsupported compute creation fails cleanly.

`mesh_set_index_buffer(mesh, buffer)` retains a native index buffer; nil disables
indexing. `mesh_index_buffer` and `mesh_vertex_buffer` return independent managed
aliases, or nil when absent. The vertex getter flushes an owned mesh's pending
CPU edits first; externally assembled meshes have no single owned vertex buffer.
`mesh_index_count` reports the selected index count. Index values are zero-based.

A compute source uses `#pragma language glsl4`, a `computemain()` entry point and
an explicit local workgroup size. Check `is_supported("glsl4")` first. Shader
stages and local dimensions are exposed by `shader_has_stage` and
`shader_threadgroup_size`. `shader_buffer_format(shader, block_name)` reflects a
storage block into the `{name, format}` array accepted by `new_buffer`. Native
std430 layout rules still apply; member arrays remain unsupported.

```scua
let compute = love.graphics.new_compute_shader(code)
let format = love.graphics.shader_buffer_format(compute, "Vertices")
let vertices = love.graphics.new_buffer(format, 4, ["vertex", "shaderstorage"])
love.graphics.shader_send_buffers(compute, "Vertices", [vertices])
love.graphics.dispatch_threadgroups(compute, 1)
```

Direct dispatch accepts positive x/y/z group counts, each at most 65535 and within
the device's limits, with a host ceiling of 16,777,216 shader invocations per call.
`dispatch_indirect(shader, arguments, index)` reads counts from a GPU buffer;
indirect contents must respect the device's limits. Compute runs on the GPU and
does not consume SCUA's script operation budget.

`draw_indirect(mesh, arguments, index, position, rotation, scale, origin)` uses a
buffer created with the `indirectarguments` usage. `index` selects a zero-based
buffer element/record. Arguments use three 32-bit integers for dispatch,
four for non-indexed drawing, or five for indexed drawing:

| Operation | Native argument order |
| --- | --- |
| Dispatch | group x, group y, group z |
| Non-indexed draw | vertex count, instance count, first vertex, first instance |
| Indexed draw | index count, instance count, first index, signed base vertex, first instance |

Check `is_supported("indirectdraw")` first. The engine validates usage, format
shape and argument offsets. GPU-produced indices and command contents follow the
underlying graphics API's rules. Per-vertex attachments are checked against the
mesh vertex count before binding; per-instance capacity is checked for direct
instanced draws.

`shader_send_textures` and `shader_send_buffers` accept arrays of managed resources,
up to the uniform's declared count and a host limit of 64. Native shader bindings
retain their resources after the original SCUA wrappers close. Like LÖVE's native
API, a driver/format error partway through binding can leave earlier entries set.
The example checks retained sampler, texel and storage-buffer arrays and compares
the final pixels, compute readback and both indirect draw layouts. The Metal
backend assigns separate consecutive binding slots to array elements and reserves
the full storage-buffer array range. The compute-stage constructor adopts its new
stage reference correctly to avoid leaking it.

## Layered, compressed, depth and compute textures

`examples/textures` exercises array and cube images, volume sampling, native
compressed block uploads, persistent depth across render passes, depth sampling,
compute image writes, GPU copies and direct/indexed/indirect shader-driven draws.
It chooses DXT1 or ASTC4x4 according to the renderer's format support. Its tiny
red compressed fixtures are reproducible with `make_fixtures.py`.

`new_texture(settings, slices)` accepts a settings record. Fields include `type`
(`2d`, `array`, `cube`, `volume`), `width`, `height`, `layers`, `format`, `mipmaps`
(`none`, `manual`, `auto`), `mipmap_count`, `render_target`, `compute_write`,
`readable`, `linear`, `dpi_scale`, `msaa`, `view_formats` and `name`. Image slices
are an array of ImageData handles, or `{data, layer, mipmap}` records for explicit
subresources. Indices are zero-based. Image data determines the actual dimensions
and format. Cube faces use native order +X, -X, +Y, -Y, +Z, -Z. Each layer/mipmap
must be present with matching dimensions and format. The host bounds textures to
4096 pixels per dimension, 256 slices and a conservative 256 MiB allocation.

```scua
let array = love.graphics.new_texture({type="array",mipmaps="auto"}, [red,blue])
let target = love.graphics.new_texture({width=64,height=64,format="rgba8",compute_write=true})
love.graphics.shader_send_textures(compute, "target", [target])
love.graphics.dispatch_threadgroups(compute, 8, 8)
```

`decode_compressed` accepts DDS/KTX/PVR/ASTC containers supported by the bundled
image handlers, bounded to 32 MiB. `compressed_info` and `compressed_bytes` expose
metadata and selected compressed blocks. `new_compressed_texture` uploads these
blocks and mipmaps without CPU decompression; the GPU must support their format.
`texture_replace_compressed` selects source and destination subresources with a
record. Ordinary `texture_replace` uploads ImageData at a layer, mipmap and pixel
offset. `texture_generate_mipmaps` regenerates configured mip levels.

`texture_info` reports dimensions, format, layers, mipmaps and usage. Query
`texture_format_supported(format, ["sample", "rendertarget", "computewrite"])`
before using optional capabilities. `texture_set_sampler` updates fields in the
existing sampler: `min_filter`, `mag_filter`, `mipmap_filter`, `wrap_u/v/w`,
`anisotropy`, `lod_bias`, `min_lod`, `max_lod` and `depth_compare` (`none` disables
comparison sampling). `texture_sampler` reads them back. `texture_view` creates
an independent managed alias retaining its parent; its record accepts `format`,
`type`, `layer_start/count`, `mipmap_start/count` and `name`. Reinterpreted formats
must be declared in `view_formats` when creating the parent. Views require Metal
or OpenGL with GLSL4 support; macOS OpenGL uses the parent texture directly.

For persistent depth, create a depth-format texture with `render_target=true`
and `readable=true` when sampling is needed. Bind it using
`set_render_targets([color], depth)`. Color/depth entries may be `{texture, layer,
mipmap}` records. `set_render_targets([], depth)` supports a depth-only pass;
`set_render_targets([])` restores the window. Depth survives rebinding until an
explicit clear. This API complements `set_canvases` with temporary depth/stencil.

`texture_read` and `texture_read_async` select a layer, mipmap and optional
`vec4(x,y,width,height)` rectangle. They return ImageData or the managed transfer
type used by the existing readback functions. Depth and compressed formats are
sampled in shaders rather than returned as ordinary ImageData.

`copy_texture_to_buffer` and `copy_buffer_to_texture` transfer GPU bytes with
optional layer, mipmap, rectangle, byte offset and pixel row width (zero means
tightly packed). Native bounds, format and alignment rules apply. `copy_texture`
copies matching-format subresources through a GPU-only temporary buffer, without
CPU readback; a copy is limited to 32 MiB. Its record selects `source_layer`,
`source_mipmap`, `source_x/y`, destination `layer`, `mipmap`, `x/y`, and `width/height`.
Copying the same source/destination subresource is rejected. Renderer capability
restrictions still apply, including macOS OpenGL's non-render-target readbacks.

`draw_from_shader`, `draw_from_shader_indexed`, `draw_from_shader_indirect` and
`draw_from_shader_indexed_indirect` draw generated vertices with a custom vertex
shader using `love_VertexID` and `love_InstanceID`, without a mesh. Indexed draws
use a native index buffer; indirect draws also require `indirectdraw` support.
Normal graphics transforms apply. The example verifies a nonzero command offset
in both indirect paths; the engine's indexed offset assignment is corrected.

## Rasterizers, glyphs, bitmap fonts and particle settings

`examples/fonts_particles` demonstrates TrueType and built-in rasterizers, glyph
pixels/metrics, image-font fallbacks, explicit BMFont pages, colored text and a
fully configured particle system. Its TrueType fixture comes from the existing
`testing/resources/font.ttf`; its image strips and bitmap pages are built in SCUA.

The `love.font` namespace wraps the native rasterizer module. Create TrueType
rasterizers with `new_rasterizer(size, encoded_bytes, settings)`, or pass nil for
the built-in font. Settings accept `hinting` (`normal`, `light`, `mono`, `none`),
`dpi_scale` and `sdf`. `new_image_rasterizer(image, glyphs, extra_spacing, dpi_scale)`
uses native separator-pixel image strips. `new_bmfont_rasterizer(definition, pages,
dpi_scale)` accepts BMFont text and an explicit array of ImageData page images;
page filenames never grant filesystem access. Font files are bounded to 32 MiB,
BMFont definitions to 1 MiB and page lists to 16 entries. Bitmap glyph regions are
validated before allocation and limited to 16 MiB each.

`rasterizer_info`, `rasterizer_glyph_info`, `rasterizer_has_glyphs` and
`rasterizer_kerning` expose native metrics and coverage. `new_glyph` accepts a
UTF-8 character; `new_glyph_codepoint` accepts a Unicode scalar. Glyph objects
support `glyph_info`, `glyph_bytes`, `glyph_clone` and `glyph_image`; the latter
returns RGBA ImageData, or nil for an empty glyph. Native luminance/alpha glyphs
are converted explicitly. Requested Unicode metadata is preserved even when
FreeType only knows the internal glyph index. Metric queries release their
FreeType temporary glyphs.

`love.graphics.new_font_from_rasterizer` retains the rasterizer. Font filtering
is exposed by `font_set_filter`/`font_filter` (the getter includes DPI scale).
`font_set_fallbacks(font, fonts)` retains up to 16 fallback rasterizers after their
original font wrappers close. Native rules require the same font type and DPI
scale; self-fallbacks are rejected. Existing width/height, line-height, baseline,
ascent/descent, kerning and coverage APIs remain available.

Colored text uses arrays of `{text, color: vec4}` records. `print_colored` and
`printf_colored` accept full drawable transforms. `font_wrap_info` returns line
text with measured widths. Cached text supports `text_set_colored`, transformed
`text_add_colored`/`text_add_wrapped`, `text_set_font`, retained `text_font` aliases,
and `text_entry_dimensions` in addition to the existing text API. Segment lists
are bounded to 4096 entries and 1 MiB of UTF-8 text.

`particles_configure(particles, settings)` covers the native particle controls in
one record. It validates the supplied values before applying them. Fields are:

- `capacity`, `rate`, `emitter_lifetime`, `lifetime: vec2`, `position: vec2`.
- `direction`, `spread`, `speed: vec2`, `rotation: vec2`, `spin: vec2`, `damping: vec2`.
- `acceleration_min/max: vec2`, `radial_acceleration: vec2`, `tangential_acceleration: vec2`.
- `sizes` (1–8 numbers), `colors` (1–8 vec4 values), `size_variation`, `spin_variation`.
- `offset: vec2`, `relative_rotation`, `insert_mode` (`top`, `bottom`, `random`).
- `area: {distribution, size: vec2, angle, relative}`; native distributions are
  `none`, `uniform`, `normal`, `ellipse`, `borderellipse`, `borderrectangle`.

Ranges use minimum/maximum pairs except `spin`, whose values are initial/final
rates and can decrease. Changing capacity resets live particles. Native allocation
failures can leave earlier applied settings changed. `particles_state` snapshots
all configuration, counters and active/paused/stopped/empty/full flags. Lifetime,
speed, acceleration and all other native getter information is included.

`particles_set_texture` changes the retained 2D texture; `particles_texture` returns
an independent alias. `particles_set_quads` retains up to 64 atlas quads; an empty
array restores the full texture and automatic offset when appropriate.
`particles_quads` returns independent managed quad aliases, each retaining its
texture even if the emitter changes or clears its quads. Existing emission,
update, move, start/stop/pause/reset and clone functions remain available. The
example uses fixed ranges for deterministic rendered particle checks.

## Resource ownership

Fonts, images, regions, shaders, text, batches, particles, meshes, math objects,
audio sources, decoders, capture devices, cursors, videos, GPU readbacks and physics
handles are opaque managed values, never pointer-shaped integers. Every
region has a managed dependency on its image: keeping a region keeps the image
alive even after the game's last direct image reference disappears.

Unreachable resources are collected every 60 rendered frames. The host drains
up to 64 queued destructors after each presented frame. Explicit
`love.graphics.release` closes immediately for script access and queues native
cleanup; releasing an already-closed alias is harmless. Access through a
closed alias faults, including after a resource slot is reused.

An image cannot be explicitly closed while a live or queued region depends on
it; that call faults as busy. Release the regions first and let a host frame
boundary drain them before releasing the image, or let automatic cleanup handle
both. Normal shutdown and script failure perform checked partition teardown,
destroying regions before images while graphics, audio and input contexts are still alive.

Other engine objects retain their native dependencies with LÖVE's reference
counts: text retains its font; batches, particles, meshes and sampler uniforms
retain textures; audio sources retain their PCM or decoder. Closing the original
SCUA wrapper does not invalidate these retained native objects. Selected cursors
also retain their native object; `set_cursor(nil)` restores the default. Completed
readbacks can return independent managed aliases of their CPU image data.

Physics uses the same bundled Box2D as LÖVE. Its upstream wrappers embed Lua
references, so this adapter supplies separate C++ ownership. Worlds own native
bodies, fixtures and joints; dropping a SCUA handle does not remove the simulated
object. Use `body_destroy`, `collider_destroy`, or `joint_destroy` for removal.
Destroying a body invalidates its fixture and joint wrappers safely. Child
wrappers retain their world until teardown. Gear joints track their source joints;
destroying either source or its body destroys dependent gears before Box2D can
access a freed joint. Positions, velocities and gravity
use pixels with 30 pixels per meter by default; the world accepts an explicit
meter scale. Forces and impulses are divided by the same scale before Box2D.

These resources refuse persistence. Save logical asset paths, frame indexes
and player records separately, then recreate GPU resources on load. There is
no automatic GPU-resource snapshot/revival in this integration.

The loader accepts encoded data up to 16 MiB and decoded dimensions up to
4096×4096. The userdata registry allows 4096 live/pending resource objects.
Native decoding/GPU allocations are outside SCUA's arena memory cap; the
dimension check currently happens after decoding. CPU image data supports concrete native
formats, with raw-only access for formats without pixel get/set support;
encoded CPU images/audio accept up to 32 MiB. Decompression and decoded audio
have a 32 MiB output ceiling. Whole-sound decoding also limits declared duration
to 120 seconds; use streaming for longer tracks. GPU readback capability depends on the renderer;
check `is_supported("copytexturetobuffer")` before reading a non-canvas texture.
Canvas readback is tested on both supported renderers.

The host finds its SCUA facade relative to the executable: `lovescua-modules/`
for the build tree, or `../share/lovescua/` for an installed/package layout.
`--print-module-path` reports the resolved directory without opening a window.
Rebuilding copies the facade files beside the executable. Moving the executable
alone is insufficient; keep its runtime modules and dynamic libraries with it.

## Package a game on macOS

```sh
python3 scua/package.py examples/instancing build/packages/instancing
./build/packages/instancing/run
```

The output directory must not already exist. The builder copies the executable,
resolves its non-system dynamic library dependencies recursively, rewrites their
load commands to `@loader_path`, and applies ad-hoc signatures to the copies.
It includes the SCUA facades, game scripts/resources/vendor dependencies, license
notices, a launcher and a SHA-256 manifest. No source binary or Homebrew library
is modified. Supply `--scua-license PATH` when the matching SDK license is not at
this workspace's sibling `scua/packaging/LICENSE` path.

The layout is `bin/lovescua`, `lib/`, `share/lovescua/`, `game/`, `licenses/`, and
`run`. Keep the complete folder together; its name and current working directory
can change. Game inputs include `.scua` files, `scua.toml`, `scua-deps.lock`, `res/`
and `deps/`; symlinked inputs are rejected so the package has explicit contents.
Launcher options such as `--save-dir` and `--user-id` retain their normal opt-in
behavior. The folder targets the architectures and macOS version requirements
of the compiled binary; notarized application bundles and other platforms remain
separate work.

For a conventional runtime installation with external libraries already available:

```sh
cmake --install build --component SCUA --prefix "$PWD/build/install"
```

That install copies the runtime and facades; the Python packaging command also
bundles the non-system libraries and a game.

## Verify

Run these from a desktop session with access to a display. Batch code changes
and run graphical tests once at the end; the full suite opens many short-lived
windows. During development, select only the affected CTest cases.

```sh
ctest --test-dir build -R '^scua_physics_controls_(metal|opengl)$' --output-on-failure -j1
ctest --test-dir build -R '^scua_(script_check|codecs|ogg_audio|modplug_no_files)$' --output-on-failure
scua examples/sprite/controller_test.scua
./build/lovescua --verify --frames 120 --fixed-dt 0.016666666666666666 \
  --screenshot build/sprites.png examples/sprite
./build/lovescua --verify --frames 120 --fixed-dt 0.016666666666666666 \
  --screenshot build/bounce.png examples/bounce
./build/lovescua --renderer opengl --verify --frames 120 \
  --fixed-dt 0.016666666666666666 examples/bounce
```

`--frames` gives a bounded graphical run; it is not a headless renderer.
`--fixed-dt` makes simulation deterministic. `--no-input` makes the window
unfocusable, suppresses keyboard/mouse/touch callbacks, and neutralizes their
polling state. CTest uses this to isolate verification from desktop input. `--verify` calls the optional
`verify()` callback after the requested frames and fails if the game quits
early. The bounce verifier checks 120 updates, the expected position and
velocity after one wall collision, and the bounded trail. `--screenshot`
writes the last frame as PNG and requires `--frames`.

CTest runs the graphics, math/data, mesh, particle, event, physics/contact/joint,
video and audio/queue examples on Metal and OpenGL, plus the filesystem example, standalone controller
checks, native-boundary cases and virtual-gamepad input. Audio tests use
`ALSOFT_DRIVERS=null` to stay silent; the normal audio demo uses the output device. Native-boundary tests also load
upstream TrueType and Ogg resources. Image tests adapt upstream dimension, viewport and
filtering checks and cover aliases, release, provider retention, garbage
collection, cleanup on failure, missing/invalid assets, resource isolation and
pack loading. Captured pixels verify cropping, scale, flipping, rotation,
origin, tint and transparency on both renderers. Rendering-example assertions
also check MRT colors, stencil masking, depth rejection and asynchronous transfers. A sandbox without WindowServer
access cannot run the graphical tests.

With `--verify`, games which create images also report live resources before
teardown and the image/quad counts released during teardown.

Editor declarations are checked in under `scua/decls`, referenced by
`scua.toml`, and generated from the host's actual registry. Refresh them after
changing the bindings:

```sh
./build/lovescua --write-decls scua/decls
```

`--check GAME` loads script definitions without a window and does not call game
callbacks. Top-level engine calls are rejected; create engine resources in `load()`.
This catches SCUA errors before running a graphical batch. It executes script
top-level code under the normal operation/memory caps, with resource reads only.

Declaration generation, `--check`, `--version`, `--print-module-path`, and package creation
do not require a display. The regular
`scua` command can format the example, but cannot run it by itself: its engine
functions are supplied by `lovescua`.

## Remaining work and compatibility

The macOS feature batch adds CPU image formats/operations/encoders, desktop settings
and asynchronous dialogs, sensor event delivery, logical saves, staged hot reload,
optional resource types and an upstream migration audit. The current registry has
710 native functions in 22 modules. [Runtime details](SCUA_RUNTIME.md) describe the
interfaces and rollback/typing limits; [validation](SCUA_VALIDATION.md) records what
was actually checked.

- SCUA frame control and opt-in multicore are implemented using the 0.39 preview fixes. The default is
  single-threaded, with bounded actor work and a host clock. See [actor integration](SCUA_ACTORS.md)
  for phase ordering, fault/reload policy, SDK provenance and source-ownership regression coverage.
  This replaces Lua thread/channel patterns; it does not reproduce their shared-state API.
- Physical controllers/sensors, microphone capture, audible playback/HRTF and some
  interactive desktop behavior still need human/hardware verification. The real
  CoreAudio output was reopened silently; this is not a listening test.
- Windows/Linux builds, distribution, notarization and application bundles remain
  outside the authorized conversion batch.
- Lua overloads, ambient filesystem/File objects, raw pointers and exact Lua Data
  binary-format compatibility are deliberately replaced or excluded. The
  [1,090-entry migration audit](SCUA_COMPATIBILITY.md) lists per-method destinations
  and boundaries. Consolidated record families are not certified parity for every
  Lua property. Graphics capabilities continue to depend on the renderer.

Existing Lua games need their scripts ported to SCUA. The examples are runnable
integration examples, not a claim that the entire upstream example/test suite has
been converted or that all Lua API behavior has been reproduced.
